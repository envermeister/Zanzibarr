## Zanzibarr v2.1 — native Samsung Tizen and LG webOS TV

Zanzibarr v2.1 brings the lazy Usenet streaming engine to **Samsung Tizen TV** and **LG webOS 26 Re:New+**, using each platform's native video player rather than libmpv. Desktop and mobile continue to use media_kit/libmpv.

### Native TV packages

| Platform | File | Target |
|---|---|---|
| **Samsung Tizen TV** | `zanzibarr-tizen-6.0-arm.tpk` | Tizen 6.0+, GCC 9.2 / ARM softfp |
| **Samsung Tizen TV (2026)** | `zanzibarr-tizen-10.0-arm.tpk` | Tizen 10 / GCC 14.2 toolchain, ARM softfp |
| **LG webOS** | `zanzibarr-webos26-arm.ipk` | webOS 26 Re:New+, LG NDK 11.2 / ARM softfp |

The CI TPKs are signed with a disposable test profile, not production credentials. The webOS IPK is a test-development package. Store submission and production signing remain separate release steps.

### One engine, native TV playback

- The same Rust NZB/NNTP/yEnc/RAR/7z/PAR2 engine and lazy localhost Range server drives playback; only watched ranges are fetched.
- Newznab, Prowlarr/NZBHydra2 and Easynews search, health badges, recent/saved searches, episode selection, natural-order queue, Up next and watch history are available in the shared TV interface.
- OpenSubtitles SRT and WebVTT files can be rendered by Flutter over the native video plane.
- Search, settings and playback controls are D-pad accessible.
- Tizen supports native audio-track enumeration/selection, saved language preference and per-stream volume. webOS uses the platform default audio track and TV system volume.
- The TV profiles deliberately exclude media_kit/libmpv and platform-specific Smart Canvas, PiP and casting features. Codec, HDR, TrueHD/DTS-HD and Dolby Vision behavior is determined by the TV media subsystem; the custom libmpv capabilities from other platforms are not implied.

### Toolchain and package integrity

- Tizen 6.0 and Tizen 10 use separate rootstraps and compiler lines. The 2026 package uses the public `tizen-10.0-device.core` rootstrap and GCC 14.2 as required by Samsung's 2026 SDK guidance.
- Both Tizen engines statically resolve unrar's C++ runtime through an archive-only native search directory. Independent `readelf` checks confirmed ELF32/ARM, soft-float ABI, the correct SONAME and no dynamic `libstdc++` dependency.
- The webOS engine carries the exact LG NDK `libstdc++.so.6` beside it and resolves that sibling through an `$ORIGIN` RPATH. The runtime is explicitly included in the FFI bundle installed into the IPK.
- The v2.1 TV packages are built by the [TV build workflow](https://github.com/envermeister/zanzibarr/actions/workflows/tv-build.yml), checked in CI with `tools/verify_tv_package.sh`, then downloaded and independently verified again before being attached to this release. GitHub's per-asset SHA-256 digests provide the published-package checksums.

### Follow-up fixes

- **RAR QuickOpen compatibility ([#7](https://github.com/envermeister/Zanzibarr/issues/7)).** A truncated QuickOpen/SERVICE payload at a volume boundary no longer invalidates complete media parts. Actual FILE truncation and split-chain validation remain strict, with regression tests for both cases.
- **Android external subtitle fonts ([#8](https://github.com/envermeister/Zanzibarr/issues/8)).** The immutable `v1.1.7-dv.8` Android libmpv package builds libass with fontconfig 2.17.1 and the libxml2 backend, enabling codepoint fallback through `/system/fonts` and `/product/fonts`. The deterministic Zanzibarr Sans/Serif/Mono fonts remain as a packaged safety net for Arabic shaping, Latin glyphs and DejaVu `♪`/`♫`/`♬`/`♩` symbols on devices whose system fonts lack them. Fontconfig and libxml2 license notices are included.
- **Low-memory playback and Android TV settings ([#9](https://github.com/envermeister/Zanzibarr/issues/9)).** Settings → Playback now provides app-wide seek-step, video/audio preset and subtitle-font defaults; a title's own saved settings retain priority. The optional low-memory mode caps streaming at two NNTP connections without changing the saved provider setting, uses smaller segment and mpv buffers, disables scrub thumbnails and limits background health checks. One- or two-connection configurations automatically select the smaller engine profile, while three or more retain existing cache/prefetch values.
- **Bounded lazy prefetch.** Completed prefetch tasks no longer chain additional downloads to end-of-file. A bounded window advances only as the player consumes segments, and starting playback stops the remaining search-health sweep. These changes apply to every resource profile and preserve the rule that paused playback must not keep fetching ahead.
- **Keyboard only on confirmation.** Android TV provider, indexer, OpenSubtitles and search text fields keep D-pad focus without opening the IME; OK enables editing and opens the keyboard for that field, and leaving the field closes editing. Touch and ordinary desktop/mobile text input keep their existing behavior.

### Verification and remaining device tests

- **334 Rust tests** and **289 Flutter tests plus 9 skips**, with Clippy and Flutter analysis clean.
- The Android media-kit AAR builds with `v1.1.7-dv.8`; all four embedded `libmpv.so` hashes match the published JAR contents, and every ABI is stripped. An arm64 release APK also builds with the matching native library and packaged fontconfig/libxml2 notices.
- Both isolated TV dependency profiles and both SDK analyzers pass.
- Package and ABI checks do not replace hardware testing. Physical Samsung/LG installation, NNTP credentials, playback, seek, subtitle rendering, codec/HDR behavior and remote-control validation remain required before store submission.
- No physical Mi Box S 3rd Gen or live-provider A/B playback test has been performed for the low-memory profile. Dolby Vision/HDR mode selection and GPU reshaping are unchanged; their behavior on the reporter's 2 GB device still requires on-device validation with representative content.
- Build and platform details are documented in [`docs/BUILDING.tv.md`](../BUILDING.tv.md).
